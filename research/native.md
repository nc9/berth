Scope: model a shared TS library on pi-ai's provider+model registry, but for compute. Consumers: Longshore (`SandboxProvider`, `packages/core/src/types.ts:278`) and Turntable (`Provider`/`ProviderInfo`, `packages/provider-sdk/src/types.ts`). Method: GitHub API/source reads, vendor docs and pricing pages, one OpenAPI file (Daytona). Prices are read on 2026-11-26 unless noted. `UNVERIFIED` = single/secondary source or not reachable. "Not documented" = the page I read did not say. Nothing was signed up for or run.

## (a) pi-ai pattern

Package is now `@earendil-works/pi-ai` v1.6.1 (https://github.com/badlogic/pi-mono/blob/main/packages/ai/package.json). The old single hand-run `scripts/generate-models.ts` no longer exists; the pipeline is `packages/ai/catalog/`.

### Generation

- Command: `npm run generate-models` = `node catalog/generate.ts --strict` (package.json scripts; `build` runs it first). Layout and build order: https://github.com/badlogic/pi-mono/blob/main/packages/ai/catalog/README.md
- Upstream sources, all fetched before anything is built (`catalog/sources/`): `models-dev.ts` (models.dev v2 `https://models.dev/experimental/v2.0/api.json`, normalised through `normalizeModelsDevModel()` because "the schema is published as experimental"), `openrouter.ts`, `vercel-ai-gateway.ts`; the README also names NVIDIA NIM and Radius modules.
- One file per provider, `catalog/providers/<id>.ts` (about 45: anthropic, openai, google, groq, ...), each calling `defineProvider({id, models: ctx => modelsDevModels(ctx, "<id>", {api, baseUrl}), compat, finalize})`. Local corrections for wrong upstream data are allowed but kept small ("prefer fixing wrong upstream data in models.dev"). `catalog/families/` holds facts true on every host (e.g. Claude effort levels).
- Output: `src/providers/data/<provider>.json` (gitignored values), committed typed wrappers `src/providers/<provider>.models.ts` (header "auto-generated by catalog/generate.ts, do not edit"), and `src/models.generated.ts` that imports them. `--json-output <dir>` also writes the public catalog JSON.
- Freshness: `.github/workflows/publish-model-catalog.yml`, cron `17 8-13 * * 1-5` (weekdays; publish job uploads only at 10:17, 12:17, 14:17 Europe/Vienna) to R2, served by pi.dev. Released clients fetch it "within hours, without updating pi" and merge it with their own code defaults (README, "Released clients"). `MINIMUM_PI_VERSION` gates catalog format changes. `models.generated.ts` itself last changed 2026-11-04 (git history), so the committed snapshot is a floor, the served catalog is the live source.

### Model type (https://github.com/badlogic/pi-mono/blob/main/packages/ai/src/types.ts, `src/providers/model-schema.ts`)

- `BaseModel`: `id`, `name`, `api`, `provider`, `baseUrl`, `input` (modalities), `inputLimits`, `cost`, `headers`.
- `Model` adds: `type?: "chat"` (image and classifier models share the registry with `type: "image" | "classifier"`), `reasoning: boolean`, `thinkingLevelMap?`, `promptCache?`, `contextWindow: number`, `maxTokens: number`, `samplingParams?`, `samplingParamsByThinkingLevel?`, `compat?` (per-API quirks, auto-detected from baseUrl if unset).
- `api` is `KnownApi | (string & {})` (open union), provider id is `KnownProvider | string`.
- `ModelCost` (units are in the schema descriptions): `input`, `output`, `cacheRead`, `cacheWrite` = "USD per million tokens"; optional `tiers: [{inputTokensAbove, input, output, cacheRead, cacheWrite}]`, "the highest matching input threshold applies to the full request". `Usage.cost` adds `total` and `totalFromProvider` (billed cost beats the catalog estimate when the provider reports it).
- Take-away for compute: the cost block is flat numbers plus tiers, with ONE unit; compute needs per-dimension units (core-second, GiB-hour, GPU-hour), so a unit field per price is required.

### Registry API (README https://github.com/badlogic/pi-mono/blob/main/packages/ai/README.md; `src/models.ts`)

- A `Models` collection holds a `Map<providerId, Provider>`. Sync reads: `models.getProviders()`, `getProvider(id)`, `getModels(provider?)`, `getModel(provider, id)` (first match by id; undefined if none), `getModelsOfType('image'|'classifier', ...)`.
- Static typed reads without a collection: `getBuiltinProviders()`, `getBuiltinModel('openai','gpt-4o-mini')` (from `@earendil-works/pi-ai/providers/all`), literal-typed ids.
- Dynamic providers: reads stay sync and return the last-known list; `await models.refresh({providers:[...]})` is the explicit async fetch; stale refreshes are discarded by a generation counter.
- Pricing kept current: catalog regenerated from models.dev/OpenRouter/Vercel and republished weekdays; `calculateCost(model, usage)` uses catalog rates and picks a tier by `inputTokensAbove`; billed cost from the provider overrides it when available.
- Custom/unknown models: `createProvider({id, auth: {apiKey: envApiKeyAuth(...)}, models: [{id, name, api, provider, baseUrl, input, cost: {input:0,...}, ...}]})` then `models.setProvider(p)`. `api` and provider id are open strings, so unknown ones type-check. Auth belongs to the provider (env var names, OAuth, ambient creds).

### models.dev as a catalog source

- v1 `https://models.dev/api.json`: provider keys; provider fields `id, env[], npm, api, name, doc, models`; model fields `id, name, family, attachment, reasoning, tool_call, structured_output, temperature, release_date, last_updated, modalities{input,output}, open_weights, limit{context,output,input?}, cost{input,output,cache_read,cache_write?,tiers?}, status, canonical_model_id`. Cost unit is not stated on the page (UNVERIFIED as per-1M tokens; pi-ai treats it so).
- v2 schema (https://github.com/anomalyco/models.dev/blob/dev/packages/core/src/schema-v2.ts): provider `{id, name, doc, env, models}`; cost per modality with `price`, `unit`, `overrides[{when, price}]`, `multipliers`. Unit enum: `token, character, image, megapixel, second, minute`; "USD per 1M for token and character, per 1 unit otherwise". Override keys include `service_tier`, `context`, `region`, `utc_hours`. Good design precedent for region/tier price overrides. It is LLM-only: there is no compute catalog on models.dev.
- Lesson: pi-ai copies upstream data by script and layers small hand corrections. No compute vendor publishes an equivalent upstream, so our registry is hand-curated with a `verified_at` and `source_url` per price (see (e)), with a few fields refreshable by API.

Legend: API facts cite vendor docs/OpenAPI. Prices as read.

### Modal

- Isolation: gVisor by default, or a VM runtime (own kernel, KVM) selected with `runtime`; GPU sandboxes only gVisor. https://modal.com/docs/guide/sandboxes, https://modal.com/docs/guide/sandbox-networking
- `Sandbox.create` params (https://modal.com/docs/reference/modal.Sandbox): `app, name, tags, image, env, secrets, timeout (default 300), idle_timeout, workdir, gpu (str), cloud, region (str|list), cpu (float|tuple), memory (int|tuple), runtime, block_network, outbound_cidr_allowlist, outbound_domain_allowlist, inbound_cidr_allowlist, volumes, pty, encrypted_ports, h2_ports, unencrypted_ports, readiness_probe, _experimental_enable_snapshot`. Methods: `exec`, `terminate`, `wait`, `from_name`, `list(app_id, tags)`, `snapshot_filesystem`, `snapshot_directory`.
- Size: free-form `cpu` (physical cores; tuple = request,limit) and `memory` MiB. No preset catalog. Min 0.125 core and 128 MiB (pricing page).
- GPUs (https://modal.com/docs/guide/gpu): strings `T4, L4, A10, L40S, A100, A100-40GB, A100-80GB, RTX-PRO-6000, H100/H100!, H200, B200/B200+, B300`; max per container 8 (A10: 4); count by suffix `H100:4` form UNVERIFIED on that page. No API to list GPU types; docs only.
- Regions: docs only (https://modal.com/docs/guide/region-selection): `us, eu, ap` plus `us-east, us-central, us-south, us-west, eu-west, eu-north, eu-south, ap-northeast, ap-southeast, ap-south, ap-melbourne, jp, kr, au, uk, ca, me, sa, af, mx`. Multiplier 1.15x broad, 1.75x narrow on usage.
- Egress: `block_network`; `outbound_cidr_allowlist`; `outbound_domain_allowlist` (beta; TLS 443 by SNI only, `*.` wildcard, ECH unsupported, fronting possible); CIDR and domain lists are additive; runtime policy change is experimental. Inbound CIDR too.
- Lifetime: `timeout` up to 24 h (https://modal.com/docs/guide/sandboxes). Filesystem snapshots yes; memory snapshots not covered on that page. Pause/resume: none (sandboxes terminate); `detach()` is client-side only.
- Exec: `sb.exec(...)` returns a process with stdout/`wait()`; each exec has its own timeout; detached by running as entrypoint. File upload API: not documented on the guide page (volumes are the documented path).
- Pricing (https://modal.com/pricing): Sandbox CPU $0.00003942 per physical core-second (= 2 vCPU, so about $0.0710 per vCPU-hour), memory $0.00000667 per GiB-second (about $0.024/GiB-hour); standard Function rates are 3x lower. GPU per second: T4 $0.000164, L4 $0.000222, A10 $0.000306, L40S $0.000542, A100-40 $0.000583, A100-80 $0.000694, RTX PRO 6000 $0.000842, H100 $0.001097, H200 $0.001261, B200 $0.001736, B300 $0.001972 (H100 about $3.95/h). Starter $0 + $30/month credits; Team $250 + $100 credits. Machine-readable: no (web page, rendered); Upstash blog lists about $0.024/GiB-h consistent.
- Logo: simple-icons slug `modal` (https://raw.githubusercontent.com/simple-icons/simple-icons/develop/slugs.md).

### Daytona

- Isolation: classes `linux-vm`, `container`, `windows` (OpenAPI enum `SandboxClass`); docs say each sandbox has "a dedicated kernel, filesystem, network stack", and fork, pause/resume and snapshot-from-sandbox are VM-class capabilities (https://www.daytona.io/docs/en/sandboxes/). Container-class isolation technology is not named. Note: product moved to closed core (see `plans/research-landscape.md`).
- OpenAPI `https://www.daytona.io/docs/openapi.json` (read 2026-11-26, v1.0). Programmatic discovery is the best of the set:
  - `GET /organizations/{id}/available-sandbox-classes` returns `AvailableSandboxClass {regionId, sandboxClass, gpuAvailable, allowedGpuTypes}`.
  - `GET /sandbox/{id}/region-quota`, `RegionQuota {maxCpuPerSandbox, maxMemoryPerSandbox, maxDiskPerSandbox, maxDiskPerGpu, maxCpuPerGpu, maxMemoryPerGpu, maxNodesPerSandbox, maxSandboxLifespan, allowedGpuTypes, total*Quota, sandboxClass, regionId}`.
  - `GET /regions`, `GET /shared-regions` (documented at https://www.daytona.io/docs/en/regions/), `GET /snapshots`, `GET /runners`, `GET /organizations/{id}/usage`, `GET /organizations/{id}/gpu-capacity`.
  - `GpuType` enum: `H100, H200, B200, B300, L40S, RTX-PRO-6000, RTX-4090, RTX-5090, MI355X`.
- `CreateSandbox` fields (OpenAPI): `snapshot, name, labels, env, user, cpu, memory, disk, gpu, gpuType (list, ordered preference), spot, kvm, cpuPerNode/memoryPerNode/diskPerNode (multi-node), target, networkBlockAll, networkAllowList, domainAllowList, outboundProxyUrl, autoStopInterval, autoPauseInterval, autoArchiveInterval, autoDeleteInterval, ttlMinutes (wall-clock TTL, destroys even if stopped/paused/archived), public, volumes, secrets, queueTimeout, otelEndpointOverride`.
- Sizes: defaults 1 vCPU/1 GiB/3 GiB; org max 4 vCPU/8 GiB/10 GiB in the docs page; stock snapshots `daytona-small` (1/1/3), `daytona-medium` (2/4/8), `daytona-large` (4/8/10). Free-form cpu/memory/disk per create. GPU: up to 8 GPUs, each GPU unit adds up to 16 vCPU, 192 GB RAM, 512 GB disk (sandboxes page).
- Regions: shared `us`, `eu`; GPU runs in reserved `earth`; dedicated and BYOC custom regions (https://www.daytona.io/docs/en/regions/). `target` selects.
- Egress (https://www.daytona.io/docs/en/network-limits/): `networkBlockAll`; `networkAllowList` = IPv4 CIDRs only, max 10; `domainAllowList` with `*.` wildcards, max 100; at most ONE of the three per create (400 otherwise); runtime update only for Tier 3/4 orgs; Tier 1/2 get org-level restrictions and cannot override.
- Lifecycle: start, stop, pause/resume (VM), archive, fork, snapshot-from-sandbox (`POST /sandbox/{id}/snapshot` body `{name, includeMemory}`), recover, auto-* intervals, spot GPU (evictions recorded as `spotEvictedAt`).
- Pricing (https://www.daytona.io/pricing): vCPU $0.0504/h, memory $0.0162/GiB-h, storage $0.000108/GiB-h (first 5 GiB free), Windows $0.0858/vCPU-h, macOS $0.0082/core-h (as printed; unit looks odd, UNVERIFIED); GPU preemptible per hour B300 $5.17, B200 $4.30, MI355X $3.56, H200 $2.87, H100 $2.47, RTX PRO 6000 $1.95, L40S $1.14, RTX 5090 $0.74, RTX 4090 $0.57; on-demand GPU prices not shown. Per-second billing; $200 free compute. Machine-readable price: no (page only). Org `usage` endpoint reports consumption, not rates.
- OS/arch: Linux, Windows, macOS appear in pricing; arch not documented.
- Logo: no simple-icons slug.

### E2B

- Isolation: Firecracker microVM per Upstash digest (https://upstash.com/blog/ai-agent-sandbox-providers-compared-2026.md, third party); E2B's template page does not name it (UNVERIFIED first-party).
- Create/template: resources fixed per template, set at build by `cpuCount` / `memoryMB` (https://docs.e2b.dev/sandbox-template). `GET /templates` (deprecated; `/v2/templates` pages) returns `cpuCount, memoryMB, diskSizeMB, maxCpuCount?, maxMemoryMB?, envdVersion, buildStatus, public, names, ...` (https://docs.e2b.dev/api-reference/templates/list-templates). So template (type) listing is API-readable per team. Region listing: not documented in what I read.
- Plan limits (https://e2b.dev/pricing): vCPU 1-8, RAM 1-8 GiB, default 2 vCPU/4 GiB; disk 10 GiB Hobby, 20 GiB Pro; no GPU; max session 1 h Hobby, 24 h Pro.
- Pause/resume (https://docs.e2b.dev/sandbox/persistence): `sbx.pause()`, `sbx.connect()`, memory + filesystem by default, `mode: 'filesystem'` option, paused kept indefinitely, pause about 4 s per GiB RAM, resume about 1 s, `onTimeout: "pause"`. Persistent snapshots exist ("Snapshotting" state).
- Egress (https://docs.e2b.dev/sandbox/internet-access): `allowInternetAccess`; `network.allowOut` (IPs, CIDRs, domains with `*.`), `network.denyOut` (IP/CIDR only); allow beats deny; domain match for HTTP:80 Host and TLS:443 SNI only; `updateNetwork()` at runtime.
- Pricing: $0.000014/vCPU-s (= $0.0504/h), $0.0000045/GiB-s (= $0.0162/h), disk free; Hobby $0 + $100 one-time credit; Pro $150/month. Machine-readable: no.
- Regions (third party, https://upstash.com/blog/ai-agent-sandbox-providers-compared-2026.md): GCP us-west1 default, AWS us-west-2/us-east-1, EU/APAC on request. Omnara lists "US, EU, Asia-Pacific" (https://docs.omnara.com/machines/providers/overview).
- Logo: no simple-icons slug.

## (d) Prior art

- **Omnara machine providers** (https://docs.omnara.com/machines/providers/overview): 12 providers: Agent37, Arker, Blaxel, boxd, CreateOS, Daytona, E2B, Freestyle, Modal, Superserve, Tenki, Unikraft Cloud. The public page describes a comparison table only (machine type: container/gVisor/microVM/full VM; custom environment; locations; sizing: CPU+memory, memory only, or set by template/snapshot; can sleep when idle) and pool config (`provider`, `provider_auth_secret_id`, `default_machine_provider_options` with e.g. `sleep_after_ms` >= 30000, `startup_script`, `snapshot`, `allowed_*` allowlists, `max_machine_cpu`, `max_machine_memory_mb`, `max_total_*`). The code-level provider interface is not on the page (not documented there; could be read in https://github.com/omnara-ai/omnara, not done). Useful: "sizing mode" as a per-provider enum and per-pool maxima.
- **ComputeSDK** (https://github.com/vercel/computesdk per search result; docs https://docs.computesdk.com/interfaces/sdk/reference.md): `compute.instances.create({size, timeout, envs, snapshotId, secrets, disk, providerOrder})`, `getById`, `list`, `destroy`; `sandbox.runCommand(cmd, {cwd, env, timeout, background, onStdout})`, `readFile/writeFile/mkdir/readdir`, `getUrl({port})`. One npm package per provider (`@computesdk/e2b`, `modal`, `daytona`, `vercel`, ...), auto-detect order from env vars, failover via `providerOrder`. Docs say available sizes depend on the provider and an invalid explicit config fails instead of silently falling back. No capability/pricing metadata; no snapshot method. Provider count conflicts between sources (8 to 9+), UNVERIFIED.
- **Upstash comparison** (https://upstash.com/blog/ai-agent-sandbox-providers-compared-2026.md): 15-provider table on isolation, persistence, price, regions, egress. Vendor-authored (Upstash sells Box), so use as pointers, not authority.
- **models.dev v2** is the closest data-model precedent (`unit`, `overrides[when]`, `multipliers`) but LLM-only.
- Our own: Turntable `ProviderInfo` (isolation, createFrom, exec, files, network.egressPolicy, resources, os, arch, cost: none|estimate|exact) and Longshore `NetworkPolicy {open|none|allowlist{domains,cidrs}}` already cover capabilities; neither has pricing, types, regions or brand metadata.

## (e) Proposed normalised records

Principles: static, hand-curated JSON/TS (like pi-ai's committed catalog) with `verified_at` + `source_url` per price; optional per-provider `refresh()` for the few API-readable parts (Daytona classes/regions/quotas, E2B templates). Reuse Turntable's `IsolationClass` and `EgressPolicy` names; add `os`/`arch` as open string unions (pi-ai `Api` pattern: `Known | (string & {})`). Fill state: Y = fillable from a documented source, P = partly, N = not documented.

### PriceBook

```
price: {
  currency: "USD" | "EUR",
  billing: "wall-clock" | "active-cpu" | "memory-only" | "active-cpu+provisioned-memory",
  granularity: "ms" | "10ms" | "s" | "min",         // Cloudflare 10 ms, Modal/E2B/Daytona per second, Vercel memory 1 min
  rates: { dimension: "vcpu"|"memory"|"disk"|"gpu"|"creation"|"egress"|"snapshot-storage",
           unit: "per-vcpu-hour"|"per-gib-hour"|"per-gb-month"|"per-gpu-hour"|"per-1M-creations"|"per-gb",
           usd: number, gpuType?: string, regionMultiplier?: number }[],
  minimums?: { vcpu?: number, memoryMiB?: number, billedMinutes?: number },   // Modal 0.125 core/128 MiB; Vercel 1 min
  monthlyFeeUsd?: number, includedCreditUsd?: number,
  verifiedAt: string, sourceUrl: string
}
```

Store ONE canonical hourly unit and keep the vendor's raw number/unit alongside (`raw: {value, unit}`) so conversions (Modal core-second to vCPU-hour, Fly monthly to hourly, boxd monthly plan) are auditable. Each conversion above (Modal $0.071/vCPU-h, E2B $0.0504/vCPU-h, Cloudflare $0.072/vCPU-h) is my arithmetic from the cited per-second prices.

### Mapping to existing interfaces

- Turntable `ProviderInfo` maps almost 1:1 onto `capabilities` + `isolation`; `cost: none|estimate|exact` becomes derived from `price.verifiedAt`/`billing`. `sandbox-size.ts` classes (`cpus`, `memoryMb`, `diskGb`, `snapshot`) become a selector over `ContainerType`; its `memoryMb` vs our `memoryMiB` needs one agreed unit.
- Longshore `NetworkPolicy {open|none|allowlist{domains,cidrs}}` should be capped by `capabilities.egress` at validation time: Daytona refuses mixed domain+CIDR and caps at 10/100; Modal accepts both; E2B deny lists reject domains. This is the check Longshore currently does by hand and the registry should expose it as `canApply(policy)`.
- Lifecycle API (uniform): `create`, `exec` (detached), `files.put/get`, `state`, `destroy`, optional `pause/resume`, optional `snapshot`. Modal and Beam lack pause; Daytona pause is VM-only, E2B pause keeps memory, Runloop suspends disk only. Make `pause`/`snapshot` optional methods gated by capability flags, as Turntable's `adopt?` and `diagnose?` already are.

### Gaps / decisions for the user

1. Confirm "boat.dev" = boxd and "Myrtle" = Morph.
2. No vendor offers machine-readable pricing; the registry needs a curated file and a scheduled human or script re-check. Only Daytona (classes, regions, quotas) and E2B (templates) can auto-refresh sizes.
3. Logos: simple-icons covers 4 of the 9 named providers; the rest need vendored brand assets (license unchecked).
4. Unverified first-party: E2B/Vercel/Cloudflare isolation and egress detail, Blaxel egress, Runloop status, boxd pricing and egress.
